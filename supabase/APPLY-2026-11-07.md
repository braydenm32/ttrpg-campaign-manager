# Applying the November 2026 security fixes

Two things go live on the server: a database change
(`supabase/migrations/20261107000000_security_audit.sql`) and a new copy of the file function
(`supabase/functions/shared-asset`). This page says how to put them live, how to check they worked
and how to undo them. It takes about 15 minutes. Nothing here deletes anyone's worlds or files.

## What changes

For players and anyone with a public wiki link:

- A link with its own words, like `[[Duke Orlov|the hooded stranger]]`, to a page they can't see now
  reaches them as just "the hooded stranger". Before, the hidden page's real name was in their copy
  (not on screen, but readable with the browser's developer tools). The same goes for a link to a
  page's GM-only nickname. Links to pages they can see, and plain `[[Duke Orlov]]` links (whose words
  are on the screen anyway), are unchanged. The example world had three of these (Captain Marrow, Lusk
  Pardew and The Ninth Stone). The first time players' apps refresh afterwards, the pages with one of
  these links show as having new writing in their News, once. Nothing to do: it clears by itself.
- Timeline ages only reach them once they can see an event in that age, which is what the timeline
  already showed them.
- Files reach them named just "Picture", "Sound", "Video" or "File", without your file names or tags.
  They never see file names in the app, so nothing changes on screen.
- A picture you're showing that they don't get (a fogged map's clean copy, say) no longer has its id
  sent.
- A random-table line that's a "#" note after an unusual space (pasted from Word, say) is hidden from
  players too, as in your preview.
- Secret passages: a lone "carriage return" (from old Mac files) now ends a line, as in the updated
  app, and players can no longer fake an "only you know" passage in their character write-ups.

For everyone at the table:

- Names: nobody can take a name someone else in the world already has (capitals, and characters
  that don't show, don't count), and names can't hold invisible or right-to-left characters. People
  get a clear message and pick again. Persian names and emoji that need a hidden joiner still work.
- Co-GM links work once: as soon as someone joins with one, it's turned off. Make a new one for the
  next co-GM. Player invite links keep working until you make a new one.
- Joining a world only happens through a link (an owner could add anyone before).

Behind the scenes: the cloud refuses a saved row whose own id or world doesn't match where it's
saved (the app never makes these, but a co-GM could have forced one, FILE-2); signed-in callers lose
database rights nothing uses (TRUNCATE and friends, PRIV-10); and one file can be at most 50 MB, as the
app already says. The file function now accepts only plain ids, so it can't be tricked into another
world's folder (ASSET-1), and sends anything that isn't a picture, sound, video or PDF as a download.

## The order

1. Publish the app update first (the one these fixes came with). The database change reads line
   breaks in secret passages the way the updated app does (`src/Markdown.tsx`), so put them live
   together, app first: a page imported from an old Mac file could otherwise show players a line the
   old app shows you as secret. Pages typed into the app never have these line breaks.
2. Deploy the file function. Old and new copies of the app both work with it.
3. Apply the database change.

## Step 1: check what's live now

Supabase dashboard → **SQL Editor** → **New query**. Paste each query, press **Run**, and note the
answers. They only read; they change nothing.

**A. Rows the new check would refuse** (must be 0; it was 0 on 7 November. If it isn't, stop and ask
for help, because those rows would stop syncing):

```sql
select count(*) as would_be_refused
from public.records
where data is not null and (
  jsonb_typeof(data) <> 'object'
  or data->>'id' is distinct from id
  or case when table_name = 'worlds' then id is distinct from world_id::text
          else data->>'worldId' is distinct from world_id::text end);
```

**B. Fingerprints of the functions being replaced:**

```sql
select p.proname, md5(pg_get_functiondef(p.oid)) as fingerprint
from pg_proc p
where p.pronamespace = 'public'::regnamespace
  and p.proname in ('player_view', 'player_text', 'member_name_ok', 'rename_member', 'join_world')
order by 1;
```

On 7 November these were:

| function | before |
| --- | --- |
| join_world | ed270858c40ab17788982c2a1f83ceea |
| member_name_ok | 9899a2bb2a24def6605484481d24ceb0 |
| player_text | 418ebeb19f4759a64124ea0e6b09a5d5 |
| player_view | 2980044f69d41e9681cac55ceb90c892 |
| rename_member | 01475ee8f32163b95b2f923f5a628d22 |

**C. Rights signed-in and signed-out callers shouldn't have** (8 rows before, none after):

```sql
select x.grantee::regrole as who, x.privilege_type as can, count(*) as tables
from pg_class c, aclexplode(c.relacl) x
where c.relnamespace = 'public'::regnamespace and c.relkind = 'r'
  and x.grantee in ('anon'::regrole, 'authenticated'::regrole)
  and x.privilege_type in ('TRUNCATE', 'REFERENCES', 'TRIGGER', 'MAINTAIN')
group by 1, 2 order by 1, 2;
```

**D. The rest:**

```sql
select
  (select file_size_limit from storage.buckets where id = 'assets') as file_limit,
  (select with_check from pg_policies where tablename = 'world_members' and policyname = 'owners manage members') as owners_can_add,
  (select count(*) from pg_trigger where tgname = 'records_check_ids') as id_check;
```

Before: `file_limit` empty, `owners_can_add` `is_world_owner(world_id)`, `id_check` 0.

**E. A copy of the functions as they are now**, for undoing (see the end). Run this, then click the
answer, copy it and save it in a text file called `before-2026-11-07.sql`:

```sql
select string_agg(pg_get_functiondef(p.oid), E';\n\n' order by p.proname) || ';' as copy
from pg_proc p
where p.pronamespace = 'public'::regnamespace
  and p.proname in ('player_view', 'player_text', 'member_name_ok', 'rename_member', 'join_world');
```

## Step 2: deploy the file function

In a terminal, in the repo folder (sign in once with `npx supabase login` if you haven't):

```sh
npx supabase functions deploy shared-asset --no-verify-jwt --project-ref ysrxumagiiaoihlhofqt
```

This sends both files in `supabase/functions/shared-asset`. Keep `--no-verify-jwt`: people with a
public wiki link aren't signed in, and the function checks who may see what itself. If it says Docker
isn't running, add `--use-api` to the end and run it again.

Check: Supabase dashboard → **Edge Functions** → `shared-asset` shows a new version. Then open one of
your worlds as a player (or its public wiki link in a private window): its pictures and maps load.

## Step 3: apply the database change

Supabase dashboard → **SQL Editor** → **New query**. Open
`supabase/migrations/20261107000000_security_audit.sql`, copy all of it, paste all of it into one
query and press **Run** once. It should say "Success. No rows returned". Run that way it goes in as
one piece: if it stops with an error, nothing has changed (save the error and ask for help). Running
it a second time does no harm.

Use the SQL Editor rather than `supabase db push` for now: the cloud's list of applied migrations
doesn't match the files (see the last section), so `db push` would try to replay every old file.

## Undoing it

Each part can be undone on its own.

- **The file function:** deploy the previous copy from git, from a second copy of the repo at the
  commit before these fixes:

  ```sh
  git worktree add ../atlas-before 4737746
  cd ../atlas-before
  npx supabase functions deploy shared-asset --no-verify-jwt --project-ref ysrxumagiiaoihlhofqt
  ```

  The updated app works with the old function too.
- **The functions in the database:** paste the `before-2026-11-07.sql` you saved in step 1 E into the
  SQL Editor and run it. (Without it: the old versions are in the repo, as the last
  `create or replace function` of each in `20261103000003_reputation.sql` (player_view),
  `20261025000000_audit_fixes.sql` (player_text) and `20261106000000_rename_players.sql`
  (member_name_ok, rename_member, join_world). Run just those blocks.)
- **The rest:**

  ```sql
  drop trigger if exists records_check_ids on public.records;
  alter policy "owners manage members" on public.world_members with check (public.is_world_owner(world_id));
  update storage.buckets set file_size_limit = null where id = 'assets';
  ```

  The rights taken away in C don't need to come back: nothing in the app uses them. The four small
  helper functions the change added (`app_trim`, `player_links`, `member_name_key`,
  `records_check_ids`) can stay; nothing uses them once the old functions are back.

## Optional: tidy up the migration history (DRIFT-1)

The cloud keeps a list of which migration files it has run, and it doesn't match the repo: it lists
19 versions with different numbers (ending with `20261029055601 review_fixes`), and the later files
were put live by hand. `supabase db push` refuses to run while they disagree, which is what we want
for now. To make `db push` usable again, tell the cloud which files are really live. This changes
only that list, never your tables or worlds. Run these in the repo folder, after step 3 (`link` asks
for the database password: Supabase dashboard → **Project Settings → Database**):

```sh
npx supabase link --project-ref ysrxumagiiaoihlhofqt
```

`npx supabase db push --include-all` applies just that file (`--include-all` because it's older than
the newest applied one).
